# 08 · 工程化与验收

> 决定动手顺序与"什么叫做完了"。玩法见 [01 游戏设计](01-游戏设计.md)，风险资产见 [05 Prompt 设计](05-Prompt设计.md)。

---

## 1. 三条原则

1. **唯一事实源**：`design-doc/` 即契约。prompt 改动必须回写 [05](05-Prompt设计.md) 并递增版本号；判定行为不对先改 prompt 再改代码，禁止在 CLI 渲染层写逻辑补丁。
2. **风险前置**：整个项目最高风险是 prompt 判定质量（不可测、不可见），最低风险是 UI。所以 M1 用 headless CLI 先把引擎钉死，UI 后行。
3. **里程碑即验收**：每个里程碑结束 = 可运行 + 验收清单全过 + git tag。没有"差不多完成了"。

---

## 2. 里程碑与验收标准

| 里程碑 | 交付物 | 验收标准 |
|---|---|---|
| **M0 CLI 骨架** | 单 crate 落位 + `config.rs` + `logging.rs` + `soup-cli list/config` | `soup-cli list` 列出 5 道内置题；缺/错 config 启动报错**可读**并给出配置与日志路径 |
| **M1 判定引擎 + 对局** | `llm.rs` + `engine.rs` + `prompts.rs` + `game.rs` + `play/ask` | ① 5 道内置题各跑 1 局：判定 JSON 解析成功率 100%；② 回放 TurtleBenchmark 真人标注（1,537 条），一致率 ≥85%；③ **hit_facts 准确性 ≥90%，partial 语义 ≥85%**；④ **反泄底 + 反注入样本 0 泄露**；⑤ 评分/胜负按 [01 §3–4](01-游戏设计.md) 本地计算正确 |
| **M2 摸鱼件 + 拉题** | `/bb` 伪装屏 + 终端标题 + Ctrl+C 优雅退出 + `fetch` | `/bb` 切换 <100ms 且能**重绘恢复**对局；Ctrl+C 落盘后退出；拉取 100 条 → ETL → 入库链路通，游标断点续拉生效；**ETL 双端一致性测试通过**（[04 §7](04-题源与ETL.md)） |
| **M3 发布** | 内置题库扩至 10 题 + 单二进制 | 单 `soup-cli.exe` 可直接运行（无需装运行时）；冷启动 <0.5s；体积 <8MB |

> M1 是全项目成败点：**判定引擎在 CLI 里跑通才算数**（不再有 GUI 里程碑）。

## 3. 测试策略

| 层 | 内容 | 工具 |
|---|---|---|
| 单测 | `engine.rs` 评分公式、命中/胜负计算、键值边界（4/5/6 条 fact、core 判定） | `cargo test`（纯函数，无需网络） |
| 单测 | `session.rs` 状态机转移、schema 迁移、原子写入 | `cargo test` |
| 单测 | ETL 规则双端一致性（[04 §7](04-题源与ETL.md)） | python 产出样本 + Rust 比对，CI 步骤 |
| 集成 | prompt 回放/红队/一致性（[05 §6](05-Prompt设计.md)） | `soup-cli` + 样本集，需真实 Key，手动/CI-optional |
| E2E | 首启（配置/报错）、对局、挂起恢复、`/bb` 伪装屏 | 手测清单（M1/M2 验收项） |

**回归纪律**：每次改 prompt，回放测试分数不得低于上一版；prompt 版本号与测试结果一起归档。

## 4. 配置与密钥

- `config.json` 进 `.gitignore`，仓库只放 `config.example.json`。
- **API Key 存 OS 凭据库**，`config.json` 不含 key（[07 §3](07-安全与异常.md)）。
- Rust 侧读取，永不进前端、永不进 git。

---

## 5. 变更纪律

- 接口（CLI 子命令 / JSON schema）变更 → 先改对应文档章节，再改代码，一次 commit。
- 每个 prompt 在 `prompts.rs` 文件头记录 `// prompt-version: vX (日期)`，行为回归时能对版本定位。
- 数据结构变更 → 递增 `schemaVersion` 并写迁移（[03 §6](03-数据结构与持久化.md)）。
- `design-doc/` 与代码在**同一仓**，避免文档漂移。
