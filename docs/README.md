## 阶段文档结构约定

每个阶段目录内从 `00` 编号：

```
docs/<N>-<阶段名>/
├── 00-总览.md      # 定位、文档地图、当前状态（阶段完结时补"封存说明"）
└── 01-xx.md …      # 契约正文（玩法数值 / 数据结构 / 接口 / 安全 / 验收）
```

- **唯一事实源规则**：任一文件变更需同步更新受影响的交叉引用；prompt 改动必须回写对应阶段
  的 Prompt 章节并递增版本号（见阶段一 [08 §5](1-turtle-cli/08-工程化与验收.md)）。
- **分层铁律**：规则/判定是纯函数（阶段一为 `src/engine.rs`）；IO/网络/终端渲染不得混入。
- 阶段一相关代码落位见 [`AGENTS.md`](../AGENTS.md) §5 任务表。

## 术语表（跨阶段通用）

| 术语 | 含义 |
|---|---|
| 汤面（surface） | 公开给玩家的谜面，有悬念但信息不全（阶段一玩法） |
| 汤底（truth） | 完整真相，仅 Rust 侧可见；展示须先结算（阶段一 [07 §2.4](1-turtle-cli/07-安全与异常.md)） |
| key_facts | 从汤底拆出的 4–6 条独立可判定事实，进度/提示/胜负的唯一锚点 |
| 判定引擎 | 与 UI 无关的纯函数层：解析 LLM 输出 → 判定/计分/胜负 |
| 摸鱼伪装 | 终端标题伪装、低对比输出、快速退出等特性（阶段一 [06](1-turtle-cli/06-摸鱼特性.md)） |
