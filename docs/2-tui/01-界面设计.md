# 阶段二 · TUI 界面 · 界面设计

> 规格正文。前置阅读：[00-总览.md](00-总览.md) 的硬约束与三阶段演进。
> 数值（行高、颜色、节流间隔）是初始建议值，实现时可微调但需回写本文。

## 1. P0 伪 TUI（零依赖，滚动式增强）

在现有 REPL 输出上叠加，**不改变任何输入行为**：

1. **判定卡片**：每次主持人判定渲染为带边框的小卡片（`┌─┐│└┘` 单行高度），
   内容 = 判定标签 + 回复 + 进度；替代现在的纯文本行。
2. **彩色判定标签**：是=绿、否=红、一半=黄、无关=暗灰（ANSI 16 色，仅 TTY 时启用）。
3. **常驻状态行**：提示符前渲染一行 `已问 n/60 · 进度 x/y · 提示 k`，随每次交互刷新（就地重写上一行）。
4. **提示符美化**：`❯ ` 替代 `> `。

降级：非 TTY 时全部退化为现有纯文本（卡片退化为单行，颜色关闭）。

## 2. P1 inline TUI（ratatui + crossterm）

### 2.1 视口

- **inline viewport**：终端底部固定 15 行，不进入 alternate screen，上方保留用户原有终端内容。
- 终端高度 < 20 行时自动退化为 P0 模式。

### 2.2 布局（15 行）

```
┌ 消息流（10 行，滚动，最新在底）──────────────┐
│ 【是】他在打嗝吗？—— 是的              │
│ 【无关】现场有第二个人吗？                │
├ 输入框（2 行）───────────────────────────┤
│ ❯ _                                      │
├ 状态栏（1 行）───────────────────────────┤
│ 水与枪 D2 · 问 3/60 · 进度 1/5 · ★ hints 1│
└──────────────────────────────────────────┘
```

- 消息流条目：玩家问（左对齐，默认色）、判定（标签彩色 + 回复）、提示（黄色前缀）、系统事件（暗灰）。
- 输入框：多行输入仅保留单行（与现 REPL 一致）；历史命令 ↑/↓ 可选。

### 2.3 事件循环

- `crossterm::event` 轮询（100ms 节流）+ `tokio::select!` 与 LLM future 并存；
  LLM 调用期间输入框显示 spinner 态，键盘事件入队不丢失。
- **命令兼容**：`/guess`、`/hint`、`/answer`、`/switch`、`/hide`、`/list`、`/status`、`/quit`
  全部保留原语义；P1 增加快捷键映射（见 §5），slash 命令不废除。

## 3. 配色（低对比主题，摸鱼优先）

| 元素 | 颜色 | 说明 |
|---|---|---|
| 背景/边框 | 默认终端色 + DarkGray 边框 | 不整块铺底色，避免"有色块"扎眼 |
| 玩家输入 | 默认前景色 | |
| 判定【是】 | Green | |
| 判定【否】 | Red | |
| 判定【一半】 | Yellow | |
| 【无关】/系统 | DarkGray | 低存在感 |
| 提示 | Yellow | |
| 状态栏 | DarkGray 底、默认前景 | |
| 汤底（结算后） | Cyan | 仅结算后出现（[阶段一 07 §2.4](../1-turtle-cli/07-安全与异常.md)） |

仅使用 ANSI 16 色（兼容 Windows Terminal / conhost / 常见 SSH 终端）。

## 4. 组件与代码结构

```
src/ui/
├── mod.rs          # 模块入口、主题常量
├── tui.rs          # P1：视口管理、事件循环、终端进出（LeaveAlternate 不用，inline 即可）
├── panels.rs       # 消息流 / 输入框 / 状态栏三个面板的渲染函数
└── fallback.rs     # P0 卡片渲染 + 非 TTY 降级输出（两套共用同一"渲染模型"）
```

- 渲染模型：面板消费的是**不可变视图 DTO**（消息列表、进度、状态、输入缓冲），由装配层从
  `Session` / `AskHostResult` 等映射而来；`ui/` 不 import `llm`，不触碰 `truth`。
- `bin/soup_cli.rs`：`play` 子命令根据 `IsTerminal` 与特性开关选择 P0/P1 渲染器装配。

## 5. 键位（P1）

| 键 | 行为 |
|---|---|
| 回车 | 提交输入（提问 / slash 命令） |
| `Ctrl+C` | 落盘退出（同 `/quit`，不弹确认） |
| `Esc` | 清空输入缓冲 |
| `↑/↓` | 输入历史（P1.1 可选） |
| `PgUp/PgDn` | 消息流滚动（P1.1 可选） |

## 6. 降级矩阵（必须全绿才算实现正确）

| 环境 | P0 | P1 |
|---|---|---|
| Windows Terminal（TTY） | 卡片+颜色 | inline 面板 |
| conhost（TTY，老终端） | 卡片（颜色尽力） | inline（16 色安全集） |
| 管道/重定向（非 TTY） | 现有纯文本 | **强制退化 P0 纯文本** |
| `--no-tui` 标志（新增） | 纯文本 | 纯文本（逃生门） |

---

## 7. 验收标准

1. 全部现有单测通过；`ui/` 新增纯函数（消息截断、布局计算）单测覆盖。
2. 降级矩阵六格逐一人工验证。
3. 对局全流程（开局→问答→/hint→/answer→结算）在 P1 下与 REPL 行为一致，会话文件互恢复无损
   （P1 存的档 P0 能续）。
4. 非 TTY 下 `cargo run -- ask` 输出与阶段一逐字节兼容（冒烟脚本依赖）。
5. `cargo clippy -D warnings` 全绿；不新增白名单外依赖（P1 需先拍板）。
