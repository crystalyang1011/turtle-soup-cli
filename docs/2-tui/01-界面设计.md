> T1 = inline TUI（本文件主体）；T2 = hub 全屏壳（§8 预留）。

## 1. T1 inline TUI（ratatui + crossterm）

### 1.1 视口

- **inline viewport**：终端底部固定 15 行，不进入 alternate screen，上方保留用户原有终端内容。
- 终端高度 < 20 行时按 §6 降级矩阵退化为纯文本模式。

### 1.2 布局（15 行）

```
┌ 消息流（10 行，滚动，最新在底）──────────────┐
│ 【是】他在打嗝吗？—— 是的              │
│ 【无关】现场有第二个人吗？                │
├ 输入框（2 行）───────────────────────────┤
│ ❯ _                                      │
├ 状态栏（1 行）───────────────────────────┤
│ 水与枪 D2 · 问 3/60 · 进度 1/5 · ★ hints 1│
└──────────────────────────────────────────┘
```

- 消息流条目：玩家问（左对齐，默认色）、判定（标签彩色 + 回复）、提示（黄色前缀）、系统事件（暗灰）。
- 输入框：仅单行输入（与阶段一 REPL 一致）；历史命令 ↑/↓ 见 §5。
- 状态栏随每次交互刷新。

### 1.3 事件循环

- `crossterm::event` 轮询（100ms 节流）+ `tokio::select!` 与 LLM future 并存；
  LLM 调用期间输入框显示 spinner 态，键盘事件入队不丢失。
- **命令兼容**：`/guess`、`/hint`、`/answer`、`/switch`、`/hide`、`/list`、`/status`、`/quit`
  全部保留原语义；T1 增加快捷键映射（见 §5），slash 命令不废除。

## 3. 组件与代码结构

```
src/ui/
├── mod.rs          # 模块入口、主题常量
├── tui.rs          # T1：视口管理、事件循环、终端进出（不用 LeaveAlternate，inline 即可）
├── panels.rs       # 消息流 / 输入框 / 状态栏三个面板的渲染函数
└── text.rs         # 非 TTY / 窄终端降级输出（与 TUI 共用同一"渲染模型"）
```

- 渲染模型：面板消费的是**不可变视图 DTO**（消息列表、进度、状态、输入缓冲），由装配层从
  `Session` / `AskHostResult` 等映射而来；`ui/` 不 import `llm`，不触碰 `truth`。
- `bin/soup_cli.rs`：`play` 子命令根据 `IsTerminal` 与 `--no-tui` 标志选择 TUI / 纯文本渲染器装配。

## 4. hub 预埋（T1 末尾，最小接口）

平台需要但不抽象过度——只落三个东西，等第二个游戏（猜词）来校正：

1. `trait Game`：`id() / title() / entry(&mut Terminal)` —— 每个游戏一个实现（海龟汤为首个注册项）；
2. 游戏注册表：`Vec<Box<dyn Game>>`，T2 的 hub 选择页直接遍历渲染；
3. `soup-cli play` = 直接进海龟汤；T2 增加 `soup-cli`（无参数）进 hub 选择页。

**禁止**：为"未来游戏"预设数据结构 / prompt 接口 / 打包格式；game pack 是独立立项（阶段三候选）。

## 5. 键位（T1）

| 键 | 行为 |
|---|---|
| 回车 | 提交输入（提问 / slash 命令） |
| `Ctrl+C` | 落盘退出（同 `/quit`，不弹确认） |
| `Esc` | 清空输入缓冲 |
| `↑/↓` | 输入历史（T1.1 可选） |
| `PgUp/PgDn` | 消息流滚动（T1.1 可选） |

## 6. 降级矩阵（必须全绿才算实现正确）

| 环境 | 行为 |
|---|---|
| Windows Terminal（TTY） | inline 面板 |
| conhost（TTY，老终端） | inline（16 色安全集） |
| 终端高度 < 20 行 | 纯文本模式（现有 REPL 输出） |
| 管道/重定向（非 TTY） | **纯文本模式**（现有 REPL 输出） |
| `--no-tui` 标志（新增） | 纯文本模式（逃生门） |

纯文本模式 = 现有 REPL 输出原样保留（脚本/冒烟依赖）。

## 7. 验收标准

1. 全部现有单测通过；`ui/` 新增纯函数（消息截断、布局计算、DTO 映射）单测覆盖。
2. §6 降级矩阵五行逐一人工验证。
3. 对局全流程（开局→问答→/hint→/answer→结算）在 TUI 下与 REPL 行为一致，会话文件互恢复无损
   （TUI 存的档纯文本模式能续）。
4. 非 TTY 下 `cargo run -- ask` 输出与阶段一逐字节兼容（冒烟脚本依赖）。
5. `cargo clippy -D warnings` 全绿；依赖仅 ratatui / crossterm（已入白名单）。
