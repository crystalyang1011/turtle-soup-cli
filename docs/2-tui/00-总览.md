# 阶段二 · TUI 界面 · 总览

> 定位：把阶段一 REPL 升级为**面板化 TUI**。玩法、判定、持久化全部复用阶段一，本阶段只动**渲染与交互层**。
>
> 阶段状态：**设计待拍板**。本文先定方向与约束，细化规格见 [01-界面设计.md](01-界面设计.md)。

---

## 0. 不变的东西（硬约束）

1. **玩法零改动**：`engine.rs` 纯函数、`game.rs` 编排、`session.rs` 持久化、prompts 契约一律不动；
   需要新数据时走 `to_public()` 式投影，不把 truth 送进渲染层（[阶段一 07 §2](../1-turtle-cli/07-安全与异常.md)）。
2. **降级铁律**：stdout 非 TTY（重定向/管道）时必须退化为**现有纯 REPL 输出**——
   `cargo run -- ask` 脚本化用法与冒烟测试依赖它。
3. **退出路径**：`/quit`、`Ctrl+C`、EOF 都必须先落盘再退（[阶段一 07 §8](../1-turtle-cli/07-安全与异常.md)）。
4. **摸鱼优先**：伪装与低调高于美观（见 §3）。

## 1. 三阶段演进（拍板项）

| 阶段 | 形态 | 依赖 | 状态 |
|---|---|---|---|
| **P0 伪 TUI** | 仍为滚动 REPL：判定卡片（边框）、彩色判定标签、常驻状态行、美化提示符 | 零新依赖 | **待拍板，可先做** |
| **P1 inline TUI** | ratatui **inline viewport**：只占终端底部 ~15 行面板（消息流 + 输入框 + 状态栏），不全屏 | 需引入 `ratatui` + `crossterm`（**AGENTS 白名单需先批准**） | 待拍板 |
| **P2 hub 壳** | 全屏 alternate screen：游戏选择页 + 游戏页 + 结算页路由 | 立项第二个游戏（猜词）后才动 | 未立项 |

**P1 选 inline 而非全屏的理由**：摸鱼场景下全屏接管过于扎眼（假标题掩护失效）；
inline 视口保留正常终端流，伪装性最好，且为 P2 全屏留了组件复用空间。
