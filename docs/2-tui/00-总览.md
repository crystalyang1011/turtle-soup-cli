# 阶段二 · TUI 平台壳 · 总览

> 定位：本阶段交付**平台的壳**——把阶段一 REPL 升级为 TUI，并为多游戏（hub）预留结构。
> 玩法、判定、持久化全部复用阶段一；本阶段只动**渲染与交互层**。
>
> 阶段状态：**设计定稿（2026-10-08）**，方向与约束见下，细化规格见 [01-界面设计.md](01-界面设计.md)。

---

## 0. 不变的东西（硬约束）

1. **玩法零改动**：`engine.rs` 纯函数、`game.rs` 编排、`session.rs` 持久化、prompts 契约一律不动；
   需要新数据时走 `to_public()` 式投影，不把 truth 送进渲染层（[阶段一 07 §2](../1-turtle-cli/07-安全与异常.md)）。
2. **降级铁律**：stdout 非 TTY（重定向/管道）时必须退化为**现有纯 REPL 输出**——
   `cargo run -- ask` 脚本化用法与冒烟测试依赖它。
3. **退出路径**：`/quit`、`Ctrl+C`、EOF 都必须先落盘再退（[阶段一 07 §8](../1-turtle-cli/07-安全与异常.md)）。
4. **摸鱼优先**：伪装与低调高于美观（见 §3）。

## 1. 演进路线（已拍板，2026-10-08）

| 阶段 | 形态 | 依赖 | 状态 |
|---|---|---|---|
| **T1 inline TUI** | ratatui **inline viewport**：只占终端底部 ~15 行面板（消息流 + 输入框 + 状态栏），不全屏 | `ratatui` + `crossterm`（**已批准加入白名单**） | **当前目标** |
| **T2 hub 壳** | 全屏 alternate screen：游戏选择页 + 游戏页 + 结算页路由 | 复用 T1 组件 | T1 交付后启动 |

> ~~伪 TUI（P0）~~：已否决（2026-10-08）——不做滚动式过渡方案，直接上 ratatui/crossterm。

**T1 选 inline 而非全屏的理由**：摸鱼场景下全屏接管过于扎眼（假标题掩护失效）；
inline 视口保留正常终端流，伪装性最好，且为 T2 全屏留了组件复用空间。

## 2. 代码落位（拍板项）

- 新增 `src/ui/` 模块：面板定义、渲染、事件循环；`src/bin/soup_cli.rs` 只保留子命令分发与装配。
- 阶段一铁律顺延：`ui/` 内**不做任何判定逻辑**，只消费 `game.rs` 的结果 DTO。
- **为平台预埋结构**：hub 选择页路由、游戏注册表（trait `Game`：标题/入口/面板装配）
  以最小接口落位，海龟汤是第一个注册项——但不做通用抽象，等第二个游戏来校正接口。

## 3. 与摸鱼特性（06）的关系

- 低对比配色基调沿用 [阶段一 06](../1-turtle-cli/06-摸鱼特性.md)；TUI 配色须提供"低对比主题"。
- 假标题逻辑不变（仅 TTY 时生效）。
- 快速退出语义不变：Esc/Ctrl+C 落盘即退。
